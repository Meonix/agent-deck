## Context

`ba-rules` asks for the `Traces:` line under each requirement heading. OpenSpec 1.5.0 validates the first body line
of a requirement for SHALL/MUST, so that layout fails strict validation. Delta specs written since
`remove-session-progress` already put the statement first.

## Goals / Non-Goals

**Goals:** main specs pass strict validation so archive can run with validation again.

**Non-Goals:** rewording any requirement; `session-goal`, `status-latency` (removed soon); the `Purpose: TBD` sections.

## Decisions

- D1 Deltas are generated by a script from the current main specs: for each requirement whose first body line is
  `Traces:`, emit a MODIFIED block of heading → statement paragraph → blank → `Traces:` → the rest verbatim. A
  requirement already in that order (session-history SRS-NFR-007) is left out.
- D2 Archive runs **with** validation; a failure there means the generator is wrong, not the specs.

## Risks / Trade-offs

- A generator slip could change wording: SC-3 checks the archived `git diff` shows only moved `Traces:` lines.
